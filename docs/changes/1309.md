### 🌐 The one-page site: `site/` and a guarded GitHub Pages workflow (#1309)

Built to the shape settled in #875 (kept in `docs/FUTURE.md`, now under Implemented).

- **`site/index.html`** is one static page:
  - what DCCore is, with a channel window showing the bot's real advert, search reply and notices, built from the
    code with invented names;
  - what it does and how people use it;
  - three steps to start;
  - how it is built, and responsible use;
  - links to the public repository, the releases, the changelog and the docs.

  No web fonts, scripts, images or frames from anywhere, so opening it tells nobody anything. Light and dark themes.
- **`.github/workflows/pages.yml`** deploys `site/` alone, from an Actions deployment, so the raw docs are never
  served. It runs on a push to `main` touching `site/**` or the workflow, and by hand. The deploy job is guarded to
  `Ninja-FSE/dccore`: Pages exists only there, so here it is skipped, not failed.
- **`docs/PUBLIC-REPO-WORKFLOW.md`, step 5:** the one-time switch in `dccore`'s Settings > Pages (Source: GitHub
  Actions), the github.io address, and the custom domain as the Pages setting plus one DNS record.
- **Tests:** `tests/test_the_site_page.py` (11 tests):
  - every link goes to a section of the page or to the public repository;
  - every file it links is in the public tree (with `docs/UPDATES-PUBLIC.md` as `docs/UPDATES.md`, and nothing
    export-ignored);
  - no tag and no CSS loads anything;
  - the deploy job is guarded, it publishes `site` and not `docs`, and neither is export-ignored.

  The identifier sweep already scans `.html`.
- **Mutation checks, 7/7 caught:**
  - a link to an export-ignored doc, or to one that does not exist;
  - a third-party script, or a CSS import;
  - a link off the project;
  - the deploy job unguarded;
  - `docs/` published instead of `site/`.
